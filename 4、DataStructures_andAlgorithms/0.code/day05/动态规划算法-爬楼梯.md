# 爬楼梯问题（青蛙跳台阶）—— 动态规划入门

***

> 适用场景：每次可以爬 **1阶** 或 **2阶**，问爬到第 `n` 级台阶共有多少种不同的走法。

***

## 1. 核心公式

### 状态转移方程

```
f(n) = f(n-1) + f(n-2)
```

这个公式是解决本问题的"灵魂"。

### 通俗翻译（倒推"最后一步"）

要想到达第 `n` 级台阶，只盯着**最后一步**看，只有两种可能：

| 最后一步 | 之前的位置 | 方法数 |
|----------|-----------|--------|
| 爬1阶 | 第 n-1 级 | f(n-1) |
| 爬2阶 | 第 n-2 级 | f(n-2) |

两种"最后一步"完全不同，不会重复，所以总方法数 = f(n-1) + f(n-2)。

***

## 2. 破解思维误区："中间交替的过程去哪了？"

### 疑惑

> 爬楼过程中，可能是 1、2、1、2 交替着上去的，公式只看最后一步，中间的花样是不是被漏掉了？

### 解答：并没有漏掉

公式不是在"模拟走路过程"，而是在做"终极分类"。

以 n=4 为例（共5种走法），用"撕掉最后一位"来证明：

**最后一脚走1阶**：撕掉最后的 `1`，剩下的前半段就是到达第3级的所有走法：
- f(3) = 3种：`[1,1,1]`, `[1,2]`, `[2,1]`
- 拼回去：`[1,1,1,1]`, `[1,2,1]`, `[2,1,1]`

**最后一脚走2阶**：撕掉最后的 `2`，剩下的前半段就是到达第2级的所有走法：
- f(2) = 2种：`[1,1]`, `[2]`
- 拼回去：`[1,1,2]`, `[2,2]`

> **结论**：无论中间怎么"交替折腾"，都已经封装在 f(n-1) 和 f(n-2) 这两个"档案袋"里了。

***

## 3. 解法一：递归（自顶向下）

### 代码实现

```python
def climb(n):
    if n == 1:
        return 1
    elif n == 2:
        return 2
    else:
        return climb(n - 1) + climb(n - 2)
```

### 递归调用过程（climb(4) 为例）

```
climb(4)
├── climb(3)
│   ├── climb(2) -> 返回 2
│   └── climb(1) -> 返回 1
└── climb(2) -> 返回 2

结果：(2 + 1) + 2 = 5
```

### 缺点

- **时间复杂度**：O(2^n)（指数级爆炸）
- **原因**：存在大量重复计算，`climb(3)` 被反复计算多次
- 当 n=40 时，基本跑不动

***

## 4. 解法二：迭代 / 动态规划（自底向上）

### 代码实现（面试推荐写法）

```python
def climb(n):
    pre = 1   # 代表 f(0)，地面
    cur = 1   # 代表 f(1)，第1级

    for _ in range(1, n):
        pre, cur = cur, pre + cur

    return cur
```

### 变量含义

在每次循环开始时：

| 变量 | 含义 |
|------|------|
| `pre` | 爬到当前级的前两级（n-2）的方法数 |
| `cur` | 爬到当前级的前一级（n-1）的方法数 |

### 执行过程推演（n=1 到 n=5）

| 当前台阶 | 计算动作 | pre | cur |
|----------|----------|-----|-----|
| 初始 | 虚拟地面和第1级 | 1（f0） | 1（f1） |
| 第2级 | f1 + f0 = 1 + 1 | 1（f1） | 2（f2） |
| 第3级 | f2 + f1 = 2 + 1 | 2（f2） | 3（f3） |
| 第4级 | f3 + f2 = 3 + 2 | 3（f3） | 5（f4） |
| 第5级 | f4 + f3 = 5 + 3 | 5（f4） | 8（f5） |

### 疑问：代码没有 `if`，怎么体现"走1阶"和"走2阶"？

"走几阶"被隐藏在加法的两侧：

| 位置 | 含义 |
|------|------|
| `pre`（加号左边） | 从 n-2 级 **跨2阶** 冲上来 |
| `cur`（加号右边） | 从 n-1 级 **跨1阶** 迈上来 |

每次加法都在执行"分类计数"的逻辑。

### 优势

| 指标 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n) | 每个数只算一次 |
| 空间 | O(1) | 只用两个变量 |

***

## 5. 边界条件："地面理论"

### 教科书边界（n=1, n=2 刹车）

递归拆解到 `n=1` 或 `n=2` 时立即返回，**不会**出现 f(0) 或 f(-1)。

### 更优雅的定义：f(0) = 1

数学上可以定义"地面"为第0级，`f(0) = 1`（站在地面上不动，算1种空方案）：

```python
def climb(n):
    if n == 0 or n == 1:
        return 1
    return climb(n - 1) + climb(n - 2)
```

递归会一直拆解到 `f(0)` 和 `f(1)`，绝不会出现 f(-1)。

### 叶子节点计数

递归拆解后的所有**叶子节点总数**就是走通的方法数：

```
n=3 的递归拆解：
f(3) = f(2) + f(1)
     = f(1) + f(0) + f(1)

叶子节点：f(1), f(0), f(1) → 共3个 → 3种走法
```

> 注意：不能只数 f(0)，否则会漏掉以 f(1) 结尾的路径。

***

## 6. 两种解法对比

| 对比维度 | 递归（方法一） | 迭代（方法二） |
|----------|---------------|---------------|
| **思维方向** | 自顶向下（从大问题拆到小问题） | 自底向上（从小问题累加到大问题） |
| **核心代码** | `return f(n-1) + f(n-2)` | `pre, cur = cur, pre + cur` |
| **时间复杂度** | O(2^n) 极慢 | O(n) 极快 |
| **空间复杂度** | O(n)（递归栈深度） | O(1)（两个变量） |
| **是否重复计算** | 大量重复 | 每个数只算一次 |
| **边界风险** | 注意 n=1,2 要刹车，避免负数 | 注意循环次数 `range(1, n)` |

***

## 7. 总结

**一句话概括本质**：

爬楼梯问题的核心不是去模拟"脚怎么交替迈"，而是利用**"最后一步分类法"**，把复杂的过程转化为简单的斐波那契数列累加。
