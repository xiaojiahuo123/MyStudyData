# 时政热点笔记·模板与约定（每日九点任务）

> 本文件是「时政热点」目录的格式约定与模板。
> **执行每次抓取任务前，请先读本文件**，再读当日笔记，保持结构一致。

- 仓库根目录：`E:\Code\MyStudyData\9、笔记`（即工作目录）
- 写入目录：`.\时政热点\`
- 命名规则：`YYYY-MM-DD 国内时政热点汇总.md`（日期按 Asia/Shanghai）
- 编辑工具：使用 `obsidian_*` 工具（obsidian_read / obsidian_write / obsidian_append / obsidian_set_property）

## 一、每次执行的标准流程

1. 取当天日期，拼出笔记路径 `时政热点/YYYY-MM-DD 国内时政热点汇总.md`。
2. 读取当日笔记：
   - 不存在 → 按下方模板新建，并写入分类内容。
   - 已存在 → 在**已有类别下补充**新条目；当天晚些时候的补充可新增「午后更新（HH:MM 补录）」章节；同步更新 frontmatter 的 `updated`。
3. `web_search` + `web_fetch` 抓取当日及前 1—2 日国内时政热点，覆盖类别：
   时政要闻、大国外交、涉台涉日与周边安全、经济与政策、民生与社会、生态环境、网络治理、科技、反腐党建、突发事件、体育（有则写，无则省略该章节）。
4. 每条写成：**加粗条目名** + 简明摘要 + 关键数据 + 来源链接（`[媒体名](URL)`）。优先新华社、央视、人民网、中国政府网、部委官网。
5. 写入后回读文件确认落盘（存在、含当日日期与章节）。若目录被清空，则整体重写当日笔记。

## 二、去重与质量红线

- 同一事件只出现一次；已写过的条目不得重复追加，只允许更新数据（如奖牌数、客流预测→实际）。
- 数字、比例、日期必须与来源一致；不确定的不写。
- 二手来源（自媒体、港媒转载）必须标注 ⚠️ 并加入「待复核事项」。
- 假期期间注意口径：外交部例行记者会国庆休会（10月1—7日），假期内无官方口径更新时，注明"待 10月8日 例行记者会核实"。

## 四、运维与排错

- **写入被拒（permission denied）**：定时执行历史上默认权限为 `read-only`。若出现写入失败，请在任务看板卡片上把权限改为 `workspace-write` 并在 UI 中确认绑定，然后手动点「执行」补跑当天。
- **卡片卡在 running**：看板「执行」为原子操作，若一次执行未正常结算，卡片会停留在 running，后续定时会被跳过。处理办法：在卡片上执行「强制结算（settle）」，使其回到 todo 列，再手动补跑。
- **9:00 没自动跑（最常见原因）**：看板定时只在 DSH Host 进程运行时触发，**停机期间错过的时点直接跳过、不补跑**（missed occurrences are skipped, never queued）。核对方法：`task_board_get` 看 `schedule.nextRunAt` 与 `executions[].startedAt`——若历史执行时间都不是 09:0x，而是 12 点前后，说明当时 Host 未运行，任务是被「手动点执行」补跑的。因此要么保证 9:00 时 DSH 处于运行状态，要么接受"开机后手动补跑当天"。
- **验证是否写入成功**：优先用 `obsidian_read` 回读当日笔记（该工具在本部署下具备写入能力）；`pwsh Get-Item/Get-ChildItem` 作为辅助核对。
- **同日下午补录**：不要另建文件，在当日笔记内新增「午后更新」章节，并更新 frontmatter 的 `updated` 字段。
- **CSV/表格**：类别表格用于速记，不要求每次填满；无内容的类别（如当天无体育消息）可整章省略，不要留空章节。

### 4.1 `obsidian_*` 工具的来源与坑（2026-10-05 排查结论）

- **来源**：这些工具**不是技能（skill），也不是 MCP server**，而是一个 DSH 插件包 `dsh-obsidian@0.2.6`（MIT）。安装位置：`C:\Users\79849\.dsh\profiles\desktop\node_modules\dsh-obsidian`；在 `~/.dsh/profiles/desktop/package.json` 的 `dsh.profile.bundles` 中挂载，插件自带 `cordis.patch.yml` 执行 `insert: id: obsidian`。它用 `node:fs` 直接读写 vault 里的 Markdown，**无需 Obsidian 的 Local REST API**，也不需要 OAuth。
- **本会话归属**：仅 `desktop` profile 装了它（`web` profile 的 bundles 里没有），所以只有 desktop 这套界面/进程才有 `obsidian_*` 工具。
- **12 个工具**：`list / search / read / frontmatter / backlinks / write / append / move / delete / set_property / delete_property / tags`。删除只移入 `.trash/`（可逆）；路径越界（`../`、绝对路径、UNC）会被拒绝；搜索与列出默认排除 `.obsidian/`、`.git/`、`.trash/`。
- **vault 根目录如何确定**：插件配置 `vaultPath` 留空时，回退到自动探测 `%APPDATA%\obsidian\obsidian.json`，取其中 `open: true` 的 vault（`find(v => v.open) ?? entries[0]`）。当前该文件里唯一 `open` 的是 `E:\Code\MyStudyData\9、笔记`，故本 vault 根 = `9、笔记` 目录本身，工具侧路径写作 `时政热点/YYYY-MM-DD 国内时政热点汇总.md`。
- ⚠️ **已知风险（尚未修，仅记录）**：探测是**动态**的，`obsidian.json` 里另有 8 个 vault（如 `E:\Obsidian Vault`）。若在 Obsidian 中切换打开别的 vault 后重启 harness／重载插件，`obsidian_*` 会**静默改指向那个仓库**，9:00 的定时任务可能把笔记写进错误的 vault 且不报错。**在本 vault 跑本任务前，请确认 Obsidian 当前打开的是 `9、笔记`。**
- **如需根除（本次未执行）**：在 `~/.dsh/profiles/desktop/cordis.patch.yml` 追加（该文件在工作区之外，写入需提权批准；改后需重启 harness 或重载插件生效）：

  ```yaml
  - id: obsidian
    config:
      vaultPath: E:\Code\MyStudyData\9、笔记
      vaultWorkspaceOnly: true
  ```

  `vaultPath` 锁定仓库路径，避免切换 vault 后被改指向；`vaultWorkspaceOnly: true` 让工具只在工作目录位于 vault 内的会话暴露（本卡片已绑定本 vault 作业区，不受影响）。
- **核对方法**：`obsidian.json` 的 `open` 标志可直接判断当前指向；工具实际根目录可用 `obsidian_list` 返回的路径名反推。
