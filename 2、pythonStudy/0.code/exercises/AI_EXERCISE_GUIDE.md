# AI 出题规范文档

本文件供 AI 出题时参考，确保练习质量一致、风格统一。

---

## 一、文件命名规范

```
exercises/
  dayXX_ex/
    ex01_xxx.py        # 练习文件
    ex01_xxx_answer.py # 对应答案文件（可选）
```

- 文件名格式: `ex` + 序号 + `_` + 主题英文名（小写+下划线）
- 示例: `ex01_strings.py`, `ex02_collections.py`
- 答案文件命名: 在原文件名后加 `_answer`（如 `ex01_strings_answer.py`）
- 答案文件为可选，若提供则与练习文件放在同一目录下

---

## 二、文件结构模板

每个练习文件必须包含以下三大部分，由浅入深：

```python
"""
DayXX 练习N - 主题名称
由浅入深掌握 XXX

参考源码: xxx/xxx.c   (相关底层实现，可选)
         xxx/xxx.py   (相关标准库)
版本: v1.0
最后更新: YYYY-MM-DD
"""

# ============================================================
#                      第一部分: 基础题
# ============================================================

print("=" * 50)
print("第一部分: 基础题")
print("=" * 50)

# ----- 题1: 标题 [必做] -----
# 题目描述（简洁明了）
# TODO: 任务要求
# 预期输出或提示（用 # ____ 标注预测结果）

# ----- 题2: 标题 [选做] -----
# ...

# ============================================================
#                    第二部分: 进阶题
# ============================================================

print("\n" + "=" * 50)
print("第二部分: 进阶题")
print("=" * 50)

# ----- 题N: 标题 [必做] -----
# ...

# ============================================================
#                    第三部分: 深入理解题
# ============================================================

print("\n" + "=" * 50)
print("第三部分: 深入理解题")
print("=" * 50)

# ----- 题N: 标题 [选做] -----
# ...
```

## 三、题目设计原则

### 3.1 难度分层

| 层级 | 占比 | 要求 | 标记 |
|------|------|------|------|
| 基础题 | ~40% | 考查语法、API 使用、基本操作 | `[必做]` |
| 进阶题 | ~35% | 考查组合运用、实际场景、边界处理 | `[必做]` |
| 深入理解题 | ~25% | 考查底层原理、性能对比、易错点辨析 | `[选做]` |

- 每道题标题后用 `[必做]` 或 `[选做]` 标注
- 基础题和进阶题默认 `[必做]`，深入理解题默认 `[选做]`
- 可根据实际情况调整，但需在题目标注中明确

### 3.2 题目类型

1. **填空预测型**：给出代码，让学生预测结果（用 `# ____` 标注）
2. **TODO 实现型**：给出要求，让学生写代码（用 `# TODO:` 标注）
3. **调试修复型**：给出错误代码，让学生找出问题（用 `# BUG:` 标注）
4. **对比辨析型**：展示相似但不同的写法，让学生理解区别
5. **实际应用型**：模拟真实场景（数据处理、权限管理等）

### 3.3 每道题的要求

- 题目描述简洁，不超过 3 行
- 必须有明确的 TODO 或预测空位
- 难度递进：同一部分内也应由易到难
- 鼓励学生先预测再运行验证
- 每道题应关联至少一个明确的知识点

## 四、注释与提示规范

```python
# TODO: 学生需要完成的任务
# ____  预测结果（让学生填空）
# BUG:  错误代码标记（调试修复型题目专用）
# 提示: 可选的引导性提示
# 注意: 需要特别留意的点
# 扩展: 选做的进阶内容
# 知识点: 本题考查的核心概念
```

- 基础题可以给提示
- 进阶题尽量不给提示
- 深入理解题可以引导思考方向

## 五、答案规范

### 5.1 答案文件格式

答案文件与练习文件结构一致，但包含完整代码和答案：

```python
"""
DayXX 练习N - 主题名称（答案版）
"""

# ----- 题1: 标题 -----
s = "Hello, Python!"
print(f"s[0]     = {s[0]}")       # ____H  ✅ 答案: H
print(f"s[-1]    = {s[-1]}")      # ____!  ✅ 答案: !
```

### 5.2 答案标注方式

- 预测题：在 `# ____` 后直接写出正确答案，用 `✅ 答案:` 标记
- TODO 题：给出参考实现代码
- BUG 题：给出修复后的代码，并说明错误原因
- 答案文件中每个 TODO 块下方用 `# 参考实现:` 注释标注

### 5.3 答案文件的可选性

- 简单练习可不提供答案文件
- 提供答案文件时，必须与练习文件同步更新
- 答案文件中可添加解题思路的额外注释

## 六、运行与验证规范

### 6.1 代码可运行性

- 每个练习文件必须能无语法错误地完整运行
- 预测题的代码必须是可执行的（不能只是注释）
- TODO 题应提供占位代码或跳过机制，避免运行时报错

### 6.2 预测题的处理方式

方式一（推荐）：代码直接运行，学生先看代码预测，再运行验证
```python
print(f"s[0] = {s[0]}")  # ____（先预测，再运行）
```

方式二：代码注释掉，学生取消注释后运行
```python
# 取消注释运行验证:
# print(f"s[0] = {s[0]}")  # ____
```

### 6.3 TODO 题的处理方式

- 提供明确的输入数据和预期输出
- 可用 `pass` 占位，避免语法错误
- 复杂题目可提供函数签名或框架代码

```python
# TODO: 实现一个函数，判断字符串是否是回文
def is_palindrome(s):
    pass  # 学生实现这里

# 验证
# print(is_palindrome("racecar"))  # 预期: True
# print(is_palindrome("hello"))    # 预期: False
```

## 七、调试修复型题目规范

### 7.1 错误代码标记

- 所有错误代码必须用 `# BUG:` 注释标记
- 每个 BUG 标记后简述错误类型
- 可在文件末尾提供 BUG 数量提示

### 7.2 错误类型分类

| 类型 | 标记 | 示例 |
|------|------|------|
| 语法错误 | `# BUG: 语法` | 缺少冒号、括号不匹配 |
| 逻辑错误 | `# BUG: 逻辑` | 边界条件错误、算法错误 |
| 类型错误 | `# BUG: 类型` | 类型不匹配、不可哈希对象 |
| 运行时错误 | `# BUG: 运行时` | 索引越界、除零错误 |

### 7.3 示例

```python
# ----- 题N: 找出以下代码中的 3 个 BUG -----
# BUG: 语法 - 缺少冒号
if x > 5
    print("大于5")

# BUG: 逻辑 - 应该用 >= 而不是 >
if x > 10:
    print("两位数")

# BUG: 类型 - 字典的 key 必须是可哈希的
d = {[1,2]: "list_key"}
```

## 八、内容覆盖要求

### 8.1 字符串相关

- 创建方式（单引号、双引号、三引号、原始字符串）
- 索引与切片（正向、反向、步长）
- 不可变性（id 变化、拼接创建新对象）
- 常用方法（replace, split, join, find, index, upper, lower, strip, startswith, endswith）
- 格式化（f-string, format, %）
- 编码相关（encode/decode, ord/chr）

### 8.2 元组相关

- 创建（括号、逗号、单元素元组、tuple()）
- 不可变性 vs 嵌套可变对象
- 与列表的区别和转换
- 解包（a, b, c = tup）
- 作为字典的 key / 集合的元素

### 8.3 集合相关

- 创建（{}、set()、推导式）
- 去重特性
- 集合运算（交集、并集、差集、对称差集）
- 子集/超集判断
- 不可哈希的可变对象不能放入集合

### 8.4 字典相关

- 创建方式（{}、dict()、推导式、fromkeys）
- 访问（[]、get、setdefault）
- 增删改（直接赋值、pop、popitem、del、clear、update）
- 遍历（keys、values、items）
- 嵌套字典
- 字典推导式

### 8.5 综合应用

- 字符串 ↔ 列表 ↔ 元组 ↔ 集合 ↔ 字典 的相互转换
- 选择合适的数据结构解决实际问题
- 性能对比（列表 vs 集合的 in 操作）

### 8.6 函数参数与拷贝相关

- 必须参数、关键字参数、默认值参数
- 不定长参数（*args、**kwargs）
- 解包传参（*、**）
- 参数传递本质（引用传递）
- 不可变对象 vs 可变对象在函数中的行为
- 浅拷贝（copy()、[:]、list()、copy.copy()）
- 深拷贝（copy.deepcopy()）
- 浅拷贝与深拷贝的区别和应用场景

### 8.7 闭包与匿名函数相关

- 函数嵌套
- 作用域链（局部 -> 嵌套 -> 全局 -> 内建）
- global 关键字
- nonlocal 关键字
- 闭包的定义和使用
- 闭包的陷阱（延迟绑定）
- lambda 表达式
- map()、filter()、reduce() 函数
- 递归函数（基准条件、递归调用）
- 文件操作（open、read、write、with语句）

### 8.8 面向对象编程相关

- 类的定义（class 关键字）
- __init__ 构造方法
- self 参数的含义
- 类属性 vs 实例属性
- 实例方法、类方法（@classmethod）、静态方法（@staticmethod）
- __slots__ 限制属性
- __del__ 析构方法
- 类方法作为工厂方法
- 属性查找顺序

### 8.9 知识点覆盖检查

出题时需检查以下知识点是否覆盖：

- [ ] 字符串：创建、索引切片、不可变性、方法、格式化、编码
- [ ] 元组：创建、不可变性、解包、作为 key
- [ ] 集合：创建、去重、运算、子集超集、可哈希性
- [ ] 字典：创建、访问、增删改、遍历、嵌套、推导式
- [ ] 综合：类型转换、数据结构选择、性能对比
- [ ] 函数参数：必须/关键字/默认值/*args/**kwargs/解包传参
- [ ] 参数传递：引用传递、不可变vs可变对象
- [ ] 拷贝：浅拷贝与深拷贝的区别和应用
- [ ] 作用域：局部/嵌套/全局/内建、global/nonlocal
- [ ] 闭包：定义、使用、延迟绑定陷阱
- [ ] 匿名函数：lambda、map、filter、reduce
- [ ] 递归：基准条件、递归调用
- [ ] 文件操作：open/read/write/with
- [ ] OOP基础：类定义、__init__、self、属性、方法

## 十、出题检查清单

出题完成后，逐项检查：

### 基本要求
- [ ] 文件结构包含三大部分（基础/进阶/深入）
- [ ] 题目数量 10-15 道（每个练习文件）
- [ ] 由浅入深，难度递进
- [ ] 包含至少 2 道预测填空题
- [ ] 包含至少 1 道实际应用题
- [ ] 包含至少 1 道底层原理/辨析题
- [ ] TODO 和 ____ 标注清晰
- [ ] 与学生已学内容衔接，不超纲
- [ ] 运行无语法错误
- [ ] 中文注释，专业术语可附英文

### 题目质量
- [ ] 每道题有明确的知识点关联
- [ ] 题目描述简洁，不超过 3 行
- [ ] 预测题的代码可直接运行验证
- [ ] TODO 题有明确的输入输出示例
- [ ] 难度标记正确（[必做]/[选做]）

### 调试题（如有）
- [ ] BUG 代码用 `# BUG:` 标记
- [ ] 标注了错误类型（语法/逻辑/类型/运行时）
- [ ] 提示了 BUG 数量

### 答案文件（如提供）
- [ ] 答案文件与练习文件同步
- [ ] 预测题答案用 `✅ 答案:` 标记
- [ ] TODO 题提供参考实现
- [ ] BUG 题提供修复说明

## 十一、版本管理

- 练习文件头部应包含版本号和最后更新日期
- 重大修改时递增版本号（v1.0 → v1.1 → v2.0）
- 答案文件必须与练习文件版本保持同步
- 修改记录可在文件末尾用注释添加

```python
# 修改记录:
# v1.1 (2026-06-11): 修复题3的预期输出错误
# v1.0 (2026-06-10): 初始版本
```
