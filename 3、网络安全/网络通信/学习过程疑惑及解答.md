## 疑惑一：路由器为什么还有二层接口和三层接口？它们有什么区别？

### 一句话结论

**"路由器只有三层口"是教科书的简化说法。** 真实设备里，路由器的三层口成本高、数量少，而很多场景根本不需要每个口都做路由，所以厂商会把交换芯片塞进路由器，或者允许端口在二层 / 三层模式之间切换。

判断一个口是几层，**不看它在什么设备上，看它能不能终结二层、能不能配 IP**。

![](.\images\路由器\Snipaste_2026-09-07_20-49-50.png)

### 一、为什么路由器还需要二层接口

1. **成本和端口密度**
   三层口每个都要占用路由表项、ACL、NAT 资源，转发时要查 FIB、重写帧头；二层口交给交换 ASIC 做线速转发，成本低得多。
   一台设备给「24 个二层口 + 2 个三层口」的成本，远低于「26 个三层口」。

2. **家用路由器本身就是这么造的**
   家用路由器那 4 个 LAN 口，本质是一颗交换芯片的**二层口**，它们再通过一个内部的 **VLANIF（三层逻辑口）** 连到路由引擎和 WAN 口。
   所以"一个路由器 4 个 LAN 口同网段互通"这件事，靠的是**二层交换**，不是路由。

3. **需要透传 VLAN**
   路由器下联交换机时，常要用 trunk 口把多个 VLAN 一起送下去，这只能是二层口（或物理口做 trunk + 三层子接口）。

4. **透明桥接场景**
   防火墙 / IPS 串进网络但不想改 IP 规划、PPPoE 桥接、把两个网段在二层打通——都要设备表现成"看不见的桥"，即二层接口。

### 二、核心区别对照表

| 对比维度 | 二层接口（交换口） | 三层接口（路由口） |
| --- | --- | --- |
| 工作层次 | 数据链路层，看 MAC 和 VLAN 标签 | 网络层，看 IP 包头 |
| 转发依据 | MAC 表：目的 MAC → 出端口 | 路由表 / FIB：目的前缀 → 下一跳 |
| 能否配 IP | 不能。IP 配在对应的 VLANIF / SVI / BVI 上 | 能，直接配在接口上 |
| 广播域 | 透传。同一 VLAN 的所有口共用一个广播域 | 终结。每个三层口各自独立，广播到此为止 |
| 自己的 MAC | 只是转发者，通常不作为通信端点 | 有 MAC 和 IP，是主机的网关，会应答 ARP |
| 收到帧怎么做 | 查 MAC 表转出去，源目 MAC 和 IP 头都不动 | 查路由表，重写二层帧头，TTL 减 1，必要时分片 |
| VLAN / STP | 有 access / trunk 之分，运行 STP 防环路 | 不参与 STP，环路靠路由协议和 TTL 兜底 |
| 典型形态 | 交换机物理口、路由器交换模块、bridge-group 成员口 | 路由器物理口、VLANIF、Loopback、Tunnel、dot1q 子接口 |
| 切换命令 | 华为 `portswitch`；思科 `switchport` | 华为 `undo portswitch`；思科 `no switchport` |

### 三、容易混淆的几种"混合形态"

- **dot1q 子接口（单臂路由）**
  物理口当 trunk 用（二层能力），上面切的 `GE0/0/0.10` 是三层口配 IP。一个物理口同时承担"传 VLAN"和"做网关"。

- **VLANIF / SVI**
  纯逻辑的三层口，没有物理实体，它对应的是一个二层 VLAN。该 VLAN 下的所有二层口共享这个网关——**家用路由器 LAN 侧就是这么工作的**。

- **BVI / BDI / bridge-group**
  把几个二层口桥成一个桥，再挂一个三层口出来配 IP。常用于把路由器临时当透明网桥用。

- **三层交换机**
  默认所有口都是二层口，`no switchport` 之后才变三层口——方向跟路由器正好相反。

### 四、配置对照

```
! 华为：三层口（路由器默认就是三层口）
interface GigabitEthernet0/0/0
 ip address 192.168.1.1 255.255.255.0

! 华为：切成二层口
interface GigabitEthernet0/0/1
 portswitch
 port link-type access
 port default vlan 10
!
interface Vlanif10                  # 该 VLAN 的三层网关
 ip address 192.168.10.1 24

! 思科：三层交换机上把二层口改成三层口
interface gi0/1
 no switchport
 ip address 192.168.1.1 255.255.255.0

! 思科：单臂路由子接口
interface gi0/0.10
 encapsulation dot1q 10
 ip address 192.168.10.1 255.255.255.0
```

### 五、两个实操坑

1. **在二层口上配 IP 一定报错**
   - 华为：`Error: The layer 2 interface cannot be configured with an IP address`
   - 思科：`IP address can't be configured on L2 links`
   
   遇到这个提示，第一反应应该是"**这个口现在是二层模式**"，而不是怀疑命令写错了。

2. **两台设备用三层口背靠背互连，不会触发 STP 阻塞**
   三层链路成环，STP 救不了你，靠的是 TTL 和路由协议自身的防环机制。
   反过来，如果误把两个口配成二层又成环，STP 会把其中一个 block 掉——这是排查"链路突然不通"时经常被忽略的一条。

### 六、记忆口诀

> **能配 IP、能进路由表的就是三层口；配不了 IP、只能划 VLAN 的就是二层口。**

## 疑惑二：AS（自治系统）到底是什么？为什么会有"不同的 AS"？

### 一句话结论

**AS（Autonomous System，自治系统）是"路由策略的边界"，不是地理边界，也不是公司边界。** 一个 AS 由一个或多个组织运营，对外呈现统一的路由视图，靠一个全球唯一的 ASN（AS 号）来标识。互联网之所以是"一堆 AS 互相连"而不是"一张大网"，根源是规模、策略、隔离和商业关系四件事必须用 AS 切分。

### 一、AS 是什么（RFC 1930 定义）

RFC 1930 的定义： **在单一、明确定义的路由策略下运行的一组 IP 前缀，由一个或多个运营商管理，对外呈现统一的路由视图。** 拆成三句话：

1. **它是"管理 + 策略"的边界。** 一个公司可以有多个 AS，一个 AS 也可以横跨多个城市。判断标准只有一条：这块网络是不是由同一套路由策略在管。
2. **每个 AS 有一个全球唯一的 ASN。** 由 IANA 分给五大 RIR（亚太 APNIC、北美 ARIN、欧洲 RIPE、拉美 LACNIC、非洲 AFRINIC），再逐级下发给 ISP 和大企业。
3. **AS 内外跑的协议是两套。** AS 内部用 IGP（OSPF、IS-IS、RIP、静态），目标是"最快到达"；AS 之间只能用 EGP，实际就是 BGP，目标是"按我的策略走"。

华为培训资料里那张"动态路由分类"图，正好是这个分工的官方表述：

![](.\images\路由器\Snipaste_2026-09-07_21-16-38.png)

按"工作区域"切：IGP 跑 AS 内部（RIP / OSPF / IS-IS），EGP 跑 AS 之间（现在事实上只剩 BGP）；按"工作机制"切：距离矢量（RIP）vs 链路状态（OSPF / IS-IS）。BGP 既跨区域又用路径向量机制，所以它单独占一类。

### 二、为什么非要分 AS（全网跑一个 OSPF 不行吗？）

四个现实原因，按重要性排：

- **规模**：全球公网 BGP 表已经 90 多万条前缀。AS 提供了一层聚合和抽象，flat 路由根本收敛不了。
- **策略**：IGP 只认度量（cost），而现实要的是"我不给某家运营商做免费中转""这条 2M 链路只做备份"。BGP 的 Local_Pref、MED、AS_PATH、Community 都是为人为策略设计的。
- **隔离与防环**：BGP 唯一的防环手段是 AS_PATH 里出现自己的号就丢弃。同时一家 AS 的配置失误不会直接扩散成全网故障。
- **商业关系**：transit（花钱买中转）、peer（免费对等）、customer（我卖给别人）——BGP 本质上是在用路由协议表达生意关系。

### 三、为什么会有"不同的 AS"——四种情况

这正是 `xingguo_r1_config.txt` 里最值得琢磨的地方。原因有四类：

#### 1. 不同机构 = 不同 AS

兴国（AS 2014）、南昌（AS 1001）、宁都（AS 3002）是三个各自有人管理、各自定策略的站点，所以各占一个号。**AS 的边界画在 eBGP 上，不画在地理位置上**——哪怕三个站点都在江西省，只要路由策略不统一，就是三个 AS。画在 `drawio` 里的拓扑如下：

![](.\images\路由器\Snipaste_2026-09-07_20-18-11.png)

对应到协议就是这张表：

| 维度 | iBGP | eBGP |
| --- | --- | --- |
| 范围 | 同一个 AS 内部（r1 ↔ r2） | 跨 AS（兴国 ↔ 南昌/宁都） |
| 典型建邻方式 | Loopback，靠 IGP 打通 | 直连接口 |
| TTL | 255，可跨多跳 | 默认 1，必须直连（`peer ebgp-max-hop` 可改） |
| 下一跳 | 默认不改，需 `next-hop-local` | 自动改成自己 |
| 防环 | 从 iBGP 学到的不再转发给 iBGP 邻居 | 靠 AS_PATH 里有没有自己 |

#### 2. 同一个机构内部也可能分多个 AS

大网络常见的拆法：并购遗留（两家合并后 AS 号不合并）、按地域拆、按业务拆（家宽/政企/移动各自一号）、国际出口与国内骨干分开。判据还是同一句话——**只要路由策略不统一，就该各用一个号**。

#### 3. 私有 AS：给不上公网的客户网络用

如果一个客户只连一家运营商、不需要向全网通告自己的路由，就没必要申请公网 AS 号，直接用私有 AS 就行。运营商在向公网通告时会执行 `remove-private-as` 把它剥掉——**私有 AS 号永远不该出现在公网 BGP 表里**。

#### 4. "不同说法"本身：16 位和 32 位两套号段

教材说法打架，多半是因为一套在讲 16 位、一套在讲 32 位（RFC 6793 之后）：

**16 位 AS 号空间（1 – 65535）**

| 号段 | 用途 |
| --- | --- |
| 1 – 64495 | 公网 AS，向 RIR 申请 |
| 64496 – 64511 | 文档示例段（RFC 5398） |
| 64512 – 65534 | 私有 AS，不进公网 |
| 65535 | 保留 |

> 另有 **23456 = AS_TRANS**，是 32 位 AS 在只支持 16 位的老设备上的转换占位符。

**32 位 AS 号空间（RFC 6793）**

| 号段 | 用途 |
| --- | --- |
| 65536 – 4199999999 | 32 位公网 AS |
| 4200000000 – 4294967295 | 32 位私有 AS |

> 写法：asplain 直接写 `4200000001`；asdot 写作 `64086.1` —— 同一个号，两种记法。

### 四、落到本项目：三个号是"借用公网号段"

`AS 2014 / 1001 / 3002` 按号段都落在 **1–64495 的公网段**，但这**不代表它们是合法申请的公网 AS**。这类行业专网（电力、轨交、水利等）极其常见的情况是：**借用公网号段自己编号，因为路由根本不外泄到互联网，所以不会跟真实持有者冲突。**

这跟之前的结论是同一个道理——**不能因为"不是 RFC1918 私网地址"就推断对方有合法公网地址**，AS 号同理。要确认只能查：

```
# 在设备上
display bgp routing-table          # 看 AS_PATH 里实际出现了哪些号
display bgp peer                   # 看邻居的 remote-as

# 在公网侧
whois AS2014                       # 查真实归属
# 或 https://bgp.he.net/AS2014     # 看公网 BGP 表里它通告了哪些前缀
```

**判断一个号是否"真公网 AS"**：它在公网 BGP 表里通告的前缀，必须归这个 AS 自己所有（whois 上 owner 匹配）。专网只是内部用，号段被借用很正常。

### 五、最容易记混的三句话

1. **AS 是路由策略的边界，不是地理边界，也不是公司边界。**
2. **同一个 AS 内跑 iBGP / IGP，跨 AS 才跑 eBGP**——判断邻居类型看 `remote-as` 跟本地是否相同，相同就是 iBGP。
3. **私有 AS 是 64512–65534，止于 65534**。老教材写成"64512–65535"是错的，65535 是保留号。再加上 32 位的 4200000000–4294967295，这就是"不同说法"的全部来源。
